# 투표만들기 미투표자 알림 설계

투표만들기 봇이 아직 투표하지 않은 사람을 채팅방에서 @멘션해 투표를 재촉한다. 방법은 두 가지다. 마감 1시간 전에 자동으로 알리는 방법이 있고, 만든 사람이 버튼을 눌러 바로 알리는 방법이 있다.

## 배경

- 20명이 있는 팀방에서 18명만 투표한 일이 있었다(2026-11-18, "11월 점심회식 2회차"). 카드에는 투표자가 15명까지만 보이므로 누가 빠졌는지 알 수 없었다.
- 빠진 사람을 찾으려면 K8s Pod에 들어가 DB와 채팅방 명단을 직접 대조해야 했다. 봇이 이 대조를 대신하고, 결과로 바로 알림까지 보내게 한다.

## 목표

- 폼에서 "종료 1시간전 미투표자알림"을 체크하면 마감 1시간 전에 미투표자를 멘션한다.
- 만든 사람이 `…` 메뉴의 "투표 종용하기"를 누르면 그 시점의 미투표자를 멘션한다.
- 알림 메시지는 모두 투표 카드를 인용한 답장으로 보낸다.

## 하지 않는 것

- 텍스트 명령(`@투표만들기 제목 / 항목…`)으로 바로 만드는 투표에는 자동 알림을 설정하는 방법을 넣지 않는다. 자동 알림은 폼에서만 켠다.
- 투표판 카드에 알림 예약 여부를 표시하지 않는다.
- 지금의 마감 타이머(`_schedule_close`)는 바꾸지 않는다.
- 익명 투표에서는 누가 투표하지 않았는지 드러내지 않는다.

## 동작

### 자동 알림 (폼 체크박스)

- 폼의 "익명 투표" 아래에 `ToggleInput` "종료 1시간전 미투표자알림"을 추가한다. 폼이 검증 오류로 다시 그려질 때도 체크 상태를 유지한다.
- 마감 시간이 비어 있는데 체크했으면 폼에 오류를 보여 준다. 문구는 "마감 시간을 정해야 미투표자 알림을 보낼 수 있습니다."로 한다. (내 판단)
- 익명 투표에서는 체크해도 무시한다. 자동 알림을 저장하지 않는다.
- 알림 시각은 `마감 시각 - 1시간`이다.
- 만든 시각부터 마감까지 1시간 이하이면, 투표판을 게시한 직후 바로 알림을 보낸다. 이때는 아직 아무도 투표하지 않았으므로 채팅방 전원이 멘션된다.

메시지:

```
[투표 카드 인용]
투표가 종료되기까지 1시간도 남지 않았어요!
@홍길동 @김민지 마감 전에 투표해주세요
```

### 수동 알림 ("투표 종용하기" 버튼)

- 투표판의 `…` 메뉴(secondary)에서 "투표 마감하기" 아래에 둔다. 마감하기 버튼처럼 투표가 열려 있을 때만 보인다.
- 만든 사람만 쓸 수 있다. 다른 사람이 누르면 그 사람에게만 "만든 사람(이름)만 투표를 종용할 수 있습니다."가 뜬다.
- 이미 마감된 투표에서 누르면 "이미 마감되었습니다."가 뜬다.
- 보낸 뒤 누른 사람에게 "미투표자 n명에게 알렸습니다."가 뜬다. (내 판단)
- 누르는 횟수는 제한하지 않는다. 만든 사람만 누를 수 있어서 남용될 위험이 낮다. (내 판단)

실명 투표 메시지:

```
[투표 카드 인용]
@홍길동 @김민지 @김철수 마감되기 전에 투표를 완료해주세요!
```

익명 투표 메시지(아무도 멘션하지 않는다):

```
[투표 카드 인용]
미투표자는 n명입니다. 마감되기 전에 투표를 완료해주세요!
```

### 공통 규칙

- **미투표자**: 채팅방 명단(Bot API `get_members`)에서 봇(`28:`로 시작하는 id)을 빼고, 그 투표에 한 표라도 넣은 `user_id`를 뺀 사람이다.
- **멘션 이름**: 채팅방 명단에 있는 표시 이름을 그대로 쓴다. 멘션은 기존 룰렛 봇처럼 `add_mention`으로 넣는다.
- **인용**: `MessageActivityInput.prepend_quote(poll.activity_id)`로 투표 카드를 인용한다. SDK 2.1.0에 있는 기능이다.
- **모두 투표했을 때**: 자동 알림은 보내지 않고 로그만 남긴다. 수동 알림은 채팅을 보내지 않고, 누른 사람에게만 "모두 투표했습니다."가 뜬다. (내 판단)
- **명단 조회 실패**: 자동 알림은 로그만 남긴다. 수동 알림은 누른 사람에게 "참여자 명단을 가져오지 못했습니다."가 뜬다. (내 판단)

## 구현 방식

### 검토한 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| A. 투표마다 메모리 타이머 | 정확한 시각에 보낸다 | 재시작하면 사라진다. 투표 생성과 봇 시작 두 곳에서 타이머를 걸어야 하고, 하나라도 빠지면 알림이 유실된다 |
| **B. 1분마다 DB 확인 (선택)** | 재시작하거나 배포해도 다음 확인 때 보낸다. 메모리에만 있는 상태가 없다 | 정해진 시각보다 최대 1분 늦을 수 있다 |

사용자가 B를 골랐다. 이 기능에서는 정확한 시각보다 빠짐없이 보내는 것이 더 중요하다.

### DB

`polls` 테이블에 칸 두 개를 추가한다. 기존 `anonymous` 칸처럼 `_migrate`에서 `ALTER TABLE`로 추가한다.

| 칸 | 타입 | 뜻 |
|---|---|---|
| `remind` | `INTEGER NOT NULL DEFAULT 0` | 자동 알림을 켰는지 나타낸다. 익명 투표는 항상 0이다 |
| `reminded_at` | `TEXT` | 자동 알림을 처리한 시각이다. 비어 있으면 아직 처리하지 않았다 |

기존 투표는 `remind = 0`이 되어 자동 알림이 가지 않는다.

### 주기 확인

- 봇이 시작되면 백그라운드 작업 하나가 60초마다 돈다.
- 대상 조건은 다음과 같다: `closed_at IS NULL`, `remind = 1`, `reminded_at IS NULL`, `closes_at - 1시간 <= 지금 < closes_at`.
- 보내기 **전에** `reminded_at`을 기록한다. 그래서 전송이 실패하면 다시 보내지 않는다. 중복으로 멘션하는 것보다 한 번 빠지는 쪽이 낫다고 판단했다. (내 판단)
- 봇이 마감 시각 전후로 꺼져 있어 `closes_at`을 지났다면 보내지 않는다.
- 활동 컨텍스트(`ctx`)가 없으므로 `app.send(conversation_id, activity, service_url=poll.service_url)`로 보낸다.
- 1시간 이하 마감인 투표는 생성 처리에서 바로 보내고 `reminded_at`을 기록한다. 주기 확인과 같은 함수를 쓴다.

## 빌더에게 남기는 것

- 주기 확인 작업에서 명단을 조회할 때 `app.api`가 `poll.service_url`로 요청하도록 맞추는 방법을 확인해야 한다. (미확인)
- 한 메시지에 넣을 수 있는 멘션 수에 Teams 제한이 있는지 확인되지 않았다. 20명 규모에서는 문제가 없다고 보지만, 큰 방에서 실패하면 로그로 남긴다. (미확인)
- `prepend_quote`와 `add_mention`을 함께 쓸 때 텍스트 순서가 의도대로 나오는지 실제 Teams에서 확인해야 한다.
- 테스트는 `vote-agent/tests/check.py`에 추가한다. 미투표자 계산, 익명 처리, 1시간 이하 즉시 알림, 중복 방지, 권한 거절, 모두 투표한 경우를 확인한다.
